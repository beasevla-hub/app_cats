Contexto do Projeto — app_cats (Sistema de Acervos Técnicos)
O que é
Sistema web interno para gestão e consulta de CATs (Certidões de Acervo Técnico) do CREA e Atestados de Capacidade Técnica. O domínio são obras de engenharia (praças, calçadas, escadarias, pavimentação etc.), muitas ligadas a contratos da Prefeitura de São Paulo e outros órgãos públicos.

O fluxo principal: PDFs de CATs → extração via IA → JSON → PostgreSQL → API REST → interface web.

Atualmente o banco tem ~15.500 serviços extraídos de ~175 CATs.

Arquitetura geral
sources_pdf/          → PDFs originais das CATs
       ↓
ingestao_acervos.py   → Envia PDF para IA (Gemini via OpenRouter), extrai dados
       ↓
outputs_json/         → ~175 arquivos JSON com metadados da CAT + lista de serviços
       ↓
import_json_to_postgres.py  → (alternativa) importa JSONs direto no PostgreSQL
       ↓
PostgreSQL (acervos_db)     → Tabelas cats + servicos
       ↓
backend/ (FastAPI)          → API REST em /api/v1
       ↓
frontend/ (Next.js)           → Interface em localhost:3000

Raiz do projeto (app_cats/)
Arquivo/Pasta	Função
README.md
Documentação principal do projeto

Mapeamento número CAT → nome interno da obra (ex: "2620150008134" → "CREA AVARÉ"). Usado na ingestão para dar apelido às obras

Prompt enviado à IA para extrair dados estruturados dos PDFs

import_json_to_postgres.py
Script standalone para importar JSONs já existentes em outputs_json/ para o PostgreSQL (schema completo, com raw_json)
normalizar_pdfs.py

outputs_json/
~175 JSONs extraídos das CATs (um por obra/CAT)
sources_pdf/
PDFs originais das certidões (não versionados)

Banco de dados (PostgreSQL — acervos_db)
Tabela cats
Campos principais: id, tipo_documento, numero_cat (unique), numero_art, profissional, registro_crea, empresa_contratada, contratante, cnpj_contratante, objeto, processo_administrativo, contrato, endereco_obra, cidade, estado, data_inicio, data_fim, area_m2, valor_contrato, apelido, arquivo_pdf, caminho_pdf, raw_json (JSONB), created_at, updated_at

Tabela servicos
Campos: id, cat_id (FK → cats.id), grupo, codigo, fonte, descricao, unidade, quantidade, pagina_pdf, ordem_na_pagina

Relação: 1 CAT → N serviços (cascade delete).

Como rodar localmente
# 1. PostgreSQL rodando com banco acervos_db criado
# 2. Backend
cd backend
pip install -r requirements.txt
cp .env.example .env   # configurar DATABASE_URL
uvicorn main:app --reload --port 8000
# 3. Frontend
cd frontend
pnpm install
cp .env.local.example .env.local   # NEXT_PUBLIC_API_URL=http://localhost:8000/api/v1
pnpm dev   # http://localhost:3000
# 4. (Opcional) Importar dados
python import_json_to_postgres.py   # importa JSONs de outputs_json/ para o banco
# 5. (Opcional) Ingerir novos PDFs
export OPENROUTER_API_KEY=...
python ingestao_acervos.py   # processa PDFs de sources_pdf/
